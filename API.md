# API Reference

All endpoints are served by the FastAPI backend under the `/api/v1` prefix. Interactive, always-up-to-date documentation is auto-generated by FastAPI and available once the backend is running:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- Raw OpenAPI schema: `http://localhost:8000/openapi.json`

This document is a human-readable overview of the same routes.

## Authentication

Authentication is a single HTTP-only `access_token` cookie (JWT), set on login/register/Google OAuth callback. There is no bearer-token header scheme — the cookie is the only auth channel. Endpoints marked **Auth required** below expect this cookie; without it they return `401`.

`GET /health` (root level, not under `/api/v1`) reports `{"status": "ok", "checks": {"database": "ok", "models": "ok"}}` with `200` when healthy, or `503` if the database is unreachable or a sentiment model failed to load.

## Auth — `/api/v1/auth`

| Method & Path | Description | Auth |
|---|---|---|
| `POST /register` | Register a new account | No |
| `POST /login` | Log in, sets the session cookie | No |
| `POST /logout` | Clear the session cookie | No |
| `GET /me` | Get the current user | Yes |
| `GET /google/login` | Start Google OAuth flow | No |
| `GET /google/callback` | Google OAuth callback | No |
| `POST /forgot-password` | Request a password reset | No |
| `POST /reset-password` | Complete a password reset | No |

## Users — `/api/v1/users`

| Method & Path | Description | Auth |
|---|---|---|
| `PATCH /me` | Update display name (cooldown-limited) | Yes |
| `DELETE /me` | Delete the current account and all its data | Yes |

## Analysis — `/api/v1/analysis`

| Method & Path | Description | Auth |
|---|---|---|
| `POST /jobs` | Create an analysis job (runs in the background) | Yes |
| `GET /jobs` | List the current user's jobs (paginated) | Yes |
| `GET /jobs/{job_id}` | Get a single job | Yes |
| `POST /jobs/{job_id}/cancel` | Cancel a running job | Yes |
| `DELETE /jobs/{job_id}` | Delete a job | Yes |
| `DELETE /jobs/clear-all` | Delete all of the current user's jobs | Yes |
| `GET /jobs/{job_id}/keywords` | Extracted keywords | Yes |
| `GET /jobs/{job_id}/topics` | Extracted topics | Yes |
| `GET /jobs/{job_id}/insights` | Job insights (cached/generated) | Yes |
| `GET /jobs/{job_id}/comments` | Analyzed comments with sentiment labels | Yes |
| `GET /jobs/{job_id}/export?format=csv\|excel\|pdf` | Export results | Yes |

## AI Insights — `/api/v1/analysis` (tag: `ai-insights`)

All lazy: generated on first request, then cached. Never return a hard `500` for "no API key" — they return a typed `status: "ok" | "partial" | "unavailable" | "error"` payload instead.

| Method & Path | Description | Auth |
|---|---|---|
| `GET /jobs/{job_id}/ai-insights/{capability}` | Job-level AI insight (executive summary, audience analysis, FAQs, topic clustering, etc.) | Yes |
| `GET /jobs/{job_id}/comment-insights/{capability}` | Per-comment AI extraction (complaints, suggestions) | Yes |
| `GET /jobs/{job_id}/audience-intelligence` | Audience Intelligence score + narrative | Yes |

## Rate limiting

Sensitive and expensive endpoints (auth, job creation, AI insights, chat) are throttled per-IP via `slowapi`, backed by Redis when `REDIS_URL` is set (shared limits across replicas) or in-memory otherwise. Exceeding a limit returns `429`.
